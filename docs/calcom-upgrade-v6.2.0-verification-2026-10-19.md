### Тестовое окружение

- Изолированная сеть podman. Выход наружу — только к `stripe.com` и `zoom.us` через собственный DNS (для проверки Google Calendar добавлен `googleapis.com`). TLS-прокси `cal.localtest.me:3443`, письма — в Mailpit, webhook — в локальный приёмник.
- Stripe: только Sandbox-ключи из окружения; события приходят через `stripe listen` с изолированной конфигурацией.
- База: копия production-дампа от 2026-10-17 (557 миграций) после скрипта очистки:
  - все webhook выключены, подключения Zoom/Google/PayPal/n8n удалены;
  - персональные данные клиентов заменены синтетическими, хост — `host@example.com`;
  - live-токены Stripe и секреты OAuth-приложений заменены заглушками. В первой версии очистки они оставались; платежи всё равно шли только через Sandbox-ключ (все сессии `cs_test_`), live-вызовов не было; снимок пересобран;
  - добавлен один тестовый webhook на локальный приёмник.
- Zoom: отдельный аккаунт владельца, тестовое OAuth-приложение. Тестовые встречи в конце удалены (8).
- Политика возврата `always` включалась только в тестовой копии (`sozo`, затем `single`). В production политика `never` не менялась.

## Откат

Скрипт: [`scripts/upgrade-v6.2.0/rollback-to-557.sql`](../scripts/upgrade-v6.2.0/rollback-to-557.sql). Выполняется одной транзакцией при остановленном новом образе, после свежего `pg_dump`.

- **Защита:** применены ровно 32 миграции v6.2.0, всего 589.
- **Webhook:** из подписок удаляются новые триггеры.
- **Схема:** обратный DDL, сгенерированный Prisma: 5 таблиц, 5 enum, 12 индексов и новые колонки удаляются, `users.startTime/endTime` возвращаются со значениями по умолчанию. Новые значения enum отображаются на старые (`no_show_updated` → `host_no_show_updated`, `system` → `unknown`, `SIGNUP` → `MANUAL`).
- **Флаги:** `pbac` и `onboarding-v3` → false, удаляются 3 новых `Feature`.
- **Права:** удаляются 3 новые `RolePermission` у `admin_role`.
- **Миграции:** удаляются 32 строки `_prisma_migrations`.

Данные, существующие только в v6.2.0, теряются; перечень — в заголовке скрипта.

**Скрипт не применяется автоматически и не является первым шагом отката.** Перед ним нужна отдельная оценка состояния базы на момент отката:
- что уже записано в новые таблицы, колонки и значения enum;
- какие брони и платежи появились после переключения;
- не изменились ли флаги.

Решение принимает владелец.

| Проверка | Результат |
|---|---|
| Схема после отката | совпадает с исходной схемой 557 (1107/1107 операторов); `Feature` и `RolePermission` как до обновления |
| Повторное обновление | 32 миграции, схема совпадает с первым обновлением (1167/1167) |
| Старый образ без SQL отката | `/session` 500 (P2022, `users.startTime`). Откатывать только образ нельзя |
| Старый образ после SQL отката, на данных кандидата | «No pending migrations»; страницы 200, в том числе брони кандидата; бронь с согласиями и встреча Zoom через подключение, созданное в кандидате; **новая оплата картой** (подтверждена, Zoom, письма, 3 webhook); перенос (старая встреча удалена); возвраты по платежам, обработанным кандидатом (карта succeeded, SEPA pending); отмена с возвратом |
| Повторное обновление после отката на живых данных | финальный кандидат применил 32 миграции, всё работает |

`Credential.encryptedKey` кандидат не заполнял (ключ шифрования не задан, как в production), поэтому удаление колонки при откате токены не теряет.

## Оставшиеся риски

1. **Google Calendar проверен на тестовом OAuth-клиенте,** production-подключение — нет. После переключения нужно сразу проверить слоты и одну тестовую бронь организатора.
2. **Откат с потерями.** Он удаляет данные, созданные только в v6.2.0. Значения `users.startTime/endTime` не восстанавливаются (в production были значения по умолчанию). Восстановление дампа остаётся крайней мерой: теряются брони и платежи после обновления.
3. **Переподключение Zoom через «удалить приложение».** Cal.com заменяет место встречи во всех событиях на Cal Video, а повторная установка добавляет Zoom лишь вторым вариантом. В production так переподключать нельзя. Поведение одинаково в обоих образах.
4. **Перенос оплаченной брони.** Новая бронь получает статус PENDING («Ожидает одобрения»), встреча не создаётся, оплата переносится. Существующий дефект, одинаковый в обоих образах.
5. **Новые функции upstream без перевода на uk.** Ключи `new_attendee_added`, `attendee_added_event_type_subject`, `booking`, `unknown` выводятся на английском. Эти функции сейчас не используются.
6. **Флаги `pbac` и `onboarding-v3`** включаются миграциями глобально. Влияние на единственного пользователя на тестовой копии не выявлено, но интерфейс администратора подробно не проверялся.
7. **Не исправлены и v6.2.0** (как в отчёте о переносе):
   - D1: промокоды 100%;
   - D3: асинхронные методы в live;
   - S5: отмена не закрывает Checkout;
   - S11: лог PaymentIntent;
   - новый `Price` на бронь;
   - S6: синхронизация возвратов;
   - уведомление при `requires_action`;
   - сырые ключи в заголовках писем;
   - отладочный лог webhook;
   - русский брендинг во всех локалях;
   - письмо клиенту при отказе SEPA не отправляется.
8. **Остановка контейнера.** Образ (и старый, и новый) не завершается по SIGTERM за 20–30 с и останавливается через SIGKILL. При переключении это нужно учесть.
